Backup storage capacity
Case type: math.

A systems administrator is planning local backup storage for the Atlas service. This dossier includes a base backup, an incremental-job register, and corrections. Storage values are whole MiB. This is a planning arithmetic exercise; do not infer compression ratios, deduplication, or unit conversions from outside knowledge.

FINAL RETENTION MEMO
Retain the Atlas base backup of 800 MiB. Also retain every Atlas incremental whose final state is retained. Ignore incrementals for other services and Atlas jobs marked deleted or failed. Required storage equals the base backup plus the retained Atlas incrementals. The target device has capacity 2000 MiB. Reserve 150 MiB for device housekeeping. Usable capacity equals device capacity minus that reserve. Storage remaining after the plan equals usable capacity minus required storage. The plan fits when the remaining storage is at least zero.

JOB RULES
Every job ID refers to a separate stored incremental. A correction changes the named field on a job; it does not create a new incremental. Size values already describe the stored output and must not be multiplied by a hypothetical replica count. Only the Atlas service is migrating to this target device. Other services remain on their existing devices.

APPROVED CORRECTIONS
Notice A replaces J03's size with 90 MiB. Notice B later replaces J03's size with 100 MiB. Notice C replaces J07's state with deleted. J07's original file was removed after verification. J03 keeps its Atlas service and retained state. A draft proposed a second base copy and a reserve of 200 MiB; both draft ideas were rejected by the final memo.

REVIEW NOTES
The base backup is listed separately from the incremental-job register. It must be included once even though it has no incremental job ID. The memo retains one base copy, so the rejected proposal for a second copy must not be applied to the final calculation.

The source register intentionally includes other services because the administrator exported the whole scheduling system. Service and state are separate filters: a retained Beacon job is irrelevant, and a failed Atlas job is also excluded. Both fields matter before sizes are summed.

The J03 notices correct an estimate of the same file. The later notice supplies its final stored size. The plan should not retain the original size as another archive or add the difference between notices as a separate storage requirement.

The housekeeping reserve describes capacity unavailable to backups. It is subtracted from the device capacity, not from individual job sizes. It is distinct from the backup files and does not create a stored incremental in the register.

The fit decision is a direct comparison between required storage and usable capacity. Report remaining MiB even if the answer would be negative, because a negative value would identify a deficit. Do not silently cap the remaining value at zero.
