Factory batch yield
Case type: math.

A factory needs 95 usable sensors for an order. Each production batch lists all manufactured units and the units rejected at final inspection. Usable units equal manufactured minus rejected. The order shortfall is max(0, order quantity minus total usable units).

FINAL PRODUCTION REGISTER
Batch A: manufactured 40; rejected 4; status released.
Batch B: manufactured 35; rejected 5; status released.
Batch C: manufactured 30; rejected 6; status released.
Batch P: manufactured 20; rejected 0; status prototype.
Batch H: manufactured 25; rejected 2; status held.

COUNTING RULES
Count only released batches. Prototype sensors are demonstration pieces, and held sensors await inspection; neither can fulfill this order. Rejected units were included in each batch's manufactured quantity, so subtract them exactly once. There are no usable units carried over from an earlier order and no other losses after inspection.

QUALITY NOTES
Batch B's initial inspection reported 7 rejects. A confirmed reinspection replaced that result with 5, already shown in the final register. Do not add the old and new reject counts. Batch C was manufactured on a different line but follows the same counting rules. Packaging cartons are not sensors and are not listed as production. A planned future run could produce 50 units, but it has not started and cannot be counted. The customer will accept a partial shipment; report the numerical shortfall rather than substituting a yes/no decision.

Q: Across released batches, what are total usable sensors, total rejected sensors, and the order shortfall?

Return JSON only with exactly these fields and types: usable_units (integer), rejected_units (integer), shortfall (integer).
Example format only; these are not reference values: {"usable_units":0,"rejected_units":0,"shortfall":0}.
